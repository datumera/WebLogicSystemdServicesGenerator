# WebLogic & OHS systemd Service Generator

A Bash utility script designed to automate the parsing of Oracle WebLogic Server domains and the creation of **systemd unit files**, **WLST automation scripts**, and **control wrappers** for WebLogic Server instances, NodeManagers, and Oracle HTTP Server (OHS) instances.

Created by **dAtUmErA**.

---

## Features

* **Automated Domain Parsing**: Extracts server definitions directly from `config.xml` using `xmllint`.
* **Systemd Unit Generation**: Automatically creates `.service` files configured for process control (`start`, `stop`, `restart`).
* **WLST Integration**: Generates WLST (`.wlst`) scripts using `nmConnect`, `nmStart`, `nmKill`, and `nmServerStatus`.
* **Interactive CLI**: Prompts for required domain, installation, and NodeManager details.
* **OHS Support**: Generates configurations for both embedded and standalone Oracle HTTP Server instances.
* **Sudoers Output**: Prints pre-configured `sudoers` lines so non-root users (`weblogic`) can execute systemctl actions securely without passwords.

---

## Prerequisites

Before running the script, ensure the following tools and prerequisites are installed on your Linux machine:

* **OS**: Linux distribution with `systemd` support.
* **User Permissions**: Execution requires `root` privileges.
* **Dependencies**: `xmllint` (package `libxml2-utils` on Debian/Ubuntu, `libxml2` on RHEL/CentOS).
* **Target Execution Directory**: Management wrapper scripts generated by this tool expect to be run from `/oracle/scripts`.

---

## Generated Files & Structure

For each detected server instance, NodeManager, or OHS instance, the script outputs three core files into the current working directory:

| Output File Extension | Description | Executed By |
| :--- | :--- | :--- |
| `<name>.service` | Systemd unit file[cite: 1]. | Systemd daemon (`/etc/systemd/system/`) |
| `start_<name>.wlst` / `stop_<name>.wlst` | Python/WLST scripts to interface with NodeManager. | WebLogic Scripting Tool (`wlst.sh`) |
| `<name>.sh` | Friendly wrapper script supporting `start`, `stop`, `status`, and `restart` actions. | `weblogic` user |

## Usage

### 1. Execute the Generator

Run the script as `root`, passing your domain's `config.xml` path as the first argument:

```bash
sudo ./WebLogicSystemdServicesGenerator.sh /path/to/weblogic/domain/config/config.xml

```

### 2. Interactive Prompts

Provide the requested configuration values when prompted:

1. **Domain Name**: Name of your WebLogic domain.


2. **Domain Path**: Full directory path to the WebLogic domain home.


3. **Binary Path**: Root directory of the Oracle WebLogic / Middleware installation.


4. **NodeManager Credentials & Host**: Username, password, hostname, port, and security protocol (`plain` or `ssl`).


5. **OHS Options**: Confirm if embedded or standalone OHS configurations should be created.



---

## Post-Installation Setup

1. **Move Systemd Unit Files**: Copy generated `.service` files to the systemd directory and reload the daemon:


```bash
cp *.service /etc/systemd/system/
systemctl daemon-reload

```


2. **Move Management Scripts**: Place all `.sh` wrapper scripts and `.wlst` files inside `/oracle/scripts`:


```bash
mkdir -p /oracle/scripts
mv *.sh *.wlst /oracle/scripts/
chown -R weblogic:weblogic /oracle/scripts

```


3. **Configure Sudoers**: Copy the `sudoers` lines output at the end of the script execution and paste them into `/etc/sudoers` or `/etc/sudoers.d/weblogic` to grant process execution permissions to the `weblogic` user.

## Managing Services

Once installed, services can be controlled using either standard `systemctl` commands or the generated wrapper scripts as the `weblogic` user:

### Using Systemd Directly

```bash
sudo systemctl start <server_name>.service
sudo systemctl stop <server_name>.service
sudo systemctl status <server_name>.service -l

```

### Using Wrapper Scripts (from `/oracle/scripts`)

```bash
./<server_name>.sh start
./<server_name>.sh stop
./<server_name>.sh status
./<server_name>.sh restart

```
